## Issue 1: Medical Questionnaire Not Visible for Patient

### Problem
When a patient logged in and tried to view their medical questionnaire, they saw the error:
> "Client profile not found"

This occurred even though a doctor had successfully created a questionnaire for that patient.

### Root Cause
The client matching logic in `loadQuestionnaire()` was too strict:
```javascript
const myClient = allClients.find(c => c.email === currentUser.username || c.phone === currentUser.username);
```

Issues with this approach:
1. **Case-sensitive email matching**: If user logged in with "John@Example.com" but client stored as "john@example.com", it wouldn't match
2. **No fallback strategy**: If no exact match found, immediately showed error
3. **No debugging information**: No console logs to help diagnose matching failures

### Solution
Implemented multi-strategy client matching with better error handling:

**File**: `/src/main/resources/static/patient.html`  
**Function**: `loadQuestionnaire()`

```javascript
function loadQuestionnaire() {
    if (!currentUser || !allClients.length) {
        console.log('No current user or clients loaded');
        return;
    }
    
    console.log('Current user:', currentUser);
    console.log('Looking for client with username:', currentUser.username);
    
    // Try multiple matching strategies
    let myClient = null;
    
    // Strategy 1: Match by email (case-insensitive)
    myClient = allClients.find(c => c.email && c.email.toLowerCase() === currentUser.username.toLowerCase());
    
    // Strategy 2: Match by phone
    if (!myClient) {
        myClient = allClients.find(c => c.phone && c.phone === currentUser.username);
    }
    
    // Strategy 3: Fallback to first available client
    if (!myClient) {
        myClient = allClients[0];
        console.log('Using first available client as fallback');
    }
    
    if (!myClient) {
        console.error('Could not find matching client for user:', currentUser.username);
        $('#questionnaire-container').html('<div class="empty-state"><i class="fas fa-exclamation-triangle"></i><p>Client profile not found. Please contact support.</p></div>');
        return;
    }
    
    console.log('Found client:', myClient);
    
    // Load questionnaire...
}
```

### Improvements
- ✅ Case-insensitive email matching
- ✅ Multiple matching strategies (email → phone → fallback)
- ✅ Comprehensive console logging for debugging
- ✅ Better error message with support contact suggestion
- ✅ Graceful degradation instead of hard failure

## Issue 2 & 3: Booking Error 500 - Internal Server Error

### Problem
When patients tried to book appointments through either flow:
- **Flow 1**: Services → Book Now → Select Doctor → Confirm
- **Flow 2**: Our Medical Team → Select Doctor → View Schedule → Book

Both resulted in HTTP 500 error:
```json
{
  "timestamp": "2026-04-06T07:33:57.572+00:00",
  "status": 500,
  "error": "Internal Server Error",
  "path": "/api/visits/book-with-slot"
}
```

### Root Cause
The `createVisitWithSlot` method in `VisitServiceImpl` was calling `copyDtoToEntity(dto, visit)` which attempted to set ALL relationships from the DTO, including `scheduleId`:

```java
private void copyDtoToEntity(VisitDto dto, Visit visit) {
    // ... other fields ...
    visit.setSchedule(scheduleRepository.findById(dto.getScheduleId())
            .orElseThrow(() -> new RuntimeException("Schedule not found")));
    // ...
}
```

However, the `/api/visits/book-with-slot` endpoint does NOT send `scheduleId` in the request because the schedule should be derived from the appointment slot:

```javascript
const bookingData = {
    clientId: clientId,
    employeeId: selectedDoctor.employeeId,
    serviceId: selectedService.serviceId,
    clinicId: selectedDoctor.clinicId,
    slotId: selectedSlot.slotId,  // Only slotId, no scheduleId!
    notes: $('#confirm-notes').val() || ''
};
```

This caused `dto.getScheduleId()` to return `null`, leading to:
```
RuntimeException: Schedule not found
```

### Solution
Refactored `createVisitWithSlot` to manually set only the required fields and derive the schedule from the slot:

**File**: `/src/main/java/com/medvisit/MedVisit/service/VisitServiceImpl.java`  
**Method**: `createVisitWithSlot(VisitDto dto, Long slotId)`

```java
@Override
@Transactional
public VisitDto createVisitWithSlot(VisitDto dto, Long slotId) {
    // Book the appointment slot first
    AppointmentSlot slot = appointmentSlotRepository.findById(slotId)
            .orElseThrow(() -> new RuntimeException("Appointment slot not found with ID: " + slotId));
    
    if (slot.getIsBooked()) {
        throw new RuntimeException("This time slot is already booked");
    }
    
    // Create the visit
    Visit visit = new Visit();
    
    // Set basic fields from DTO
    visit.setVisitDateTime(null); // Will be set from slot
    visit.setStatus(dto.getStatus());
    visit.setNotes(dto.getNotes());
    
    // Set relationships from DTO
    visit.setClient(clientRepository.findById(dto.getClientId())
            .orElseThrow(() -> new RuntimeException("Client not found with ID: " + dto.getClientId())));
    visit.setEmployee(employeeRepository.findById(dto.getEmployeeId())
            .orElseThrow(() -> new RuntimeException("Employee not found with ID: " + dto.getEmployeeId())));
    visit.setService(serviceRepository.findById(dto.getServiceId())
            .orElseThrow(() -> new RuntimeException("Service not found with ID: " + dto.getServiceId())));
    visit.setClinic(clinicRepository.findById(dto.getClinicId())
            .orElseThrow(() -> new RuntimeException("Clinic not found with ID: " + dto.getClinicId())));
    
    // Set visit date/time and schedule from the slot
    Schedule schedule = slot.getSchedule();
    visit.setSchedule(schedule);
    visit.setVisitDateTime(java.time.LocalDateTime.of(schedule.getDate(), slot.getStartTime()));
    
    Visit savedVisit = visitRepository.save(visit);
    
    // Mark slot as booked and link to visit
    slot.setIsBooked(true);
    slot.setVisit(savedVisit);
    appointmentSlotRepository.save(slot);
    
    return toDto(savedVisit);
}
```

### Key Changes
1. ✅ Removed `copyDtoToEntity()` call that was trying to set non-existent `scheduleId`
2. ✅ Manually set each relationship with proper error messages including IDs
3. ✅ Derived `schedule` from `slot.getSchedule()` instead of DTO
4. ✅ Set `visitDateTime` from slot's schedule date and start time
5. ✅ Better error messages with specific IDs for easier debugging

## Technical Details

### Client Matching Logic
The system now uses a three-tier matching strategy:

1. **Primary**: Email match (case-insensitive)
   - Handles variations like "John@Example.com" vs "john@example.com"
   
2. **Secondary**: Phone number match (exact)
   - For users who login with phone number
   
3. **Fallback**: First available client
   - Prevents hard failures in development/testing
   - Logs warning for investigation
   - In production, you'd want proper user-client mapping table

### Visit Creation Flow
```
POST /api/visits/book-with-slot
    ↓
VisitController.createWithSlot()
    ↓
VisitServiceImpl.createVisitWithSlot(dto, slotId)
    ↓
1. Find and validate appointment slot
2. Create Visit entity
3. Set relationships from DTO (client, employee, service, clinic)
4. Derive schedule from slot.getSchedule()
5. Set visitDateTime from slot
6. Save visit
7. Mark slot as booked
8. Link slot to visit
9. Return VisitDto
```

### Why Schedule Must Come From Slot
The appointment slot already contains the schedule reference:
```
AppointmentSlot → Schedule → Employee + Date
```

Storing `scheduleId` separately in the booking request would be:
- Redundant (already in slot)
- Error-prone (could mismatch)
- Unnecessary complexity

By deriving it from the slot, we ensure consistency.
